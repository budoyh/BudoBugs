# Contributing

Contributions must preserve authorization, evidence, and license boundaries. Do not contribute live credentials, private program materials, undisclosed findings, copied third-party prompts/payloads, or unreviewed generated output.

Before opening a change:

1. Keep runtime changes, documentation, fixtures, and third-party updates separately reviewable.
2. For any third-party code, image, ruleset, or material, update `docs/research/LICENSE_MATRIX.md` and `THIRD_PARTY_NOTICES.md` with exact source, revision, license evidence, distribution boundary, and review date.
3. GPL/AGPL/proprietary components remain behind an external process or container boundary unless a legal review explicitly approves another design.
4. Do not make `PASS` claims without an executor-generated receipt.
5. Run the closest available checks and report commands and outcomes. If Docker, credentials, or a license are absent, report the honest blocked status.

Release-focused changes must not claim an SBOM, signature, checksum, image digest, or external compatibility test unless the referenced artifact exists and is attached or reproducibly generated.
